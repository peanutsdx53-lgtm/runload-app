# Release security / privacy acceptance gates — RunLoad (2026-10-10)

This document records the current source-code security boundaries for an **unreleased** research application. It is not a claim of complete protection or medical/clinical validation.

1. **E-01 / user-controlled HTML**: independently trace attacker-originated record text, backup inspection/errors, GPX names, photos, map labels, consultation reports and URL fragment parameters into HTML/URL/SVG sinks; exercise hostile strings in real browser with CSP active. The support-guidance `returnTo` attribute injection was corrected and regression-guarded in the associated change. Still outstanding: complete route-by-route attack proof; do not mark E-01 PASS based on one fix.
2. **GPS locality / external map**: saved GPS traces stay in browser origin storage; mapping must require explicit opt-in before requests to OpenStreetMap. Tile requests reveal the viewed area to the imagery provider even without a complete GPS-log upload. Review export/delete, permission-denial behavior and side effects independently.
3. **Plaintext backup confidentiality**: a portable JSON backup is **not** separately password-encrypted by RunLoad. Existing export/restore controls and saved file permissions are insufficient to claim cryptographic confidentiality. Any change introducing password encryption, recovery keys, or significant UX is a product decision and needs user consultation; preserve current readable backup data and do not introduce undocumented automatic encryption.
4. **GitHub Pages same-origin limitation**: browser localStorage protection is by **origin**, not repository path; if RunLoad is hosted at `https://<account>.github.io/runload-app/`, other independently deployed project pages on the **same** `https://<account>.github.io` origin can execute JavaScript with access to that origin's localStorage. Storage key prefixes and the `runload-app/` path do **not** form a security isolation boundary. A dedicated origin / deployment strategy is a *release hosting requirement for review* when evaluating other pages under the same account. Do not claim the origin is isolated without verifying deployment architecture. CSP blocks foreign scripts in RunLoad's page but cannot restrict JavaScript executing on another page of the same origin.
5. **HTTPS / offline / permissions**: verify actual deployment HTTPS, content dependencies, Service Worker scope, denied storage/Geolocation, and full offline real-device operation at the appropriate gates. Do not equate headless-browser CI to physical mobile testing.
6. **Untrusted external links**: enumerate literal approved sources and ensure target-blank links use suitable `rel` protection; prohibit constructing arbitrary external destinations from restored user data.

Audit statuses remain **E-01 PARTIAL / E-07 PARTIAL** until corresponding acceptance evidence is complete. Source/public assets and science originals are immutable unless an independently justified authorized fix is required.
