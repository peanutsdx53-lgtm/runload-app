# G-03 Old-record semantic preservation — independent regression (2026-10-10)

## Contract and scope

G-03's acceptance condition is that a previously stored record and its model output **must never be silently rewritten into calculations of a newer model**. This is an implementation integrity property, not a claim about clinical meaning, all earlier product versions, or real-device storage conditions.

The supported retained model versions are `runload-primary-regional-reference100-v3.0` (historical read-only) and `runload-primary-regional-reference100-v3.1` (current). Their output semantic versions and region-specific comparison signatures are distinct. An unknown model is not silently interpreted as either supported version. The original v3.0 test snapshot was generated by the original v3.0 code and contains no actual user's records.

## Independent finding and correction

Previously `core/internal/recordWorkflow.js` selected only a matching old model result, or a current-model candidate for recovery. When a historical v3.0 result existed but the record revision had changed and no current-model result existed, selection returned `null` too early. Consequently the experience indicated no regional result **without retaining a structured explanation** that a historical version existed but could not be used. The archived result itself was not modified.

Now the fallback selects the existing historical v3.0 result **only when no current-model candidate exists**. The existing validation then detects `SOURCE_RECORD_REVISION_MISMATCH`, rejects presentation of that stale regional value, and produces `HISTORIC_ARCHIVE_UNAVAILABLE`. It preserves the old result and its model ID; it neither performs a v3.1 calculation nor automatically edits stored data. If a valid current-model result exists, it retains priority.

## Test coverage

`tests/g03HistoricLifecycleIndependentAudit.test.mjs` provides eight independent Node tests:

1. Fifteen repetitions through loadExperience, latest, all experiences, search, and repository lookup of original v3.0 backup, with byte-preserving snapshot assertion
2. Portable export, preflight inspection, repeated restore of an actual original-v3.0 generated synthetic backup
3. **Explicit user edit** generates separate v3.1 result, retains exact original v3.0 model result, blocks comparisons across all 12 region signatures, and survives backup transfer
4. An unknown old-model ID remains unmodified in raw storage; portable backup is blocked instead of reinterpreted
5. A corrupted historical calculation is read-only, unavailable, and is not automatically repaired with v3.1
6. New record revision with old-result revision mismatch returns `HISTORIC_ARCHIVE_UNAVAILABLE` and `SOURCE_RECORD_REVISION_MISMATCH` without mutation — **red before fix, green after**
7. Delete and undo retains the original v3.0 saved result and model snapshot identically
8. Four missing/null/changed timestamp variants do not persist fabricated v3.1 results during reading

Existing `a03HistoricV30Import`, `a03ModelVersionCoexistence`, `g03LegacyModelReadOnlyBoundary`, and G-01 restore/undo safety tests are also run as part of the full Node CI suite. This test file does not include real customer data.

## Interpretation of PASS

If all Node/Chromium CI checks and independent git/CURRENT verification pass, G-03 technical acceptance is PASS: old results do not silently change model identity or numeric meaning. This **does not** make G-01 all-device backup/IndexedDB/permissions, F screen terminology, C-04 Live Server, D-01/D-02 actual offline device validation, or A-10 human explanation PASS. User-facing UI/UX changes remain on hold.
