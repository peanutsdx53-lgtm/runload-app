# RunLoad Record Input UI Prototype V0.1 — Design Policy

## Baseline
Current App V1.5R2 remains the functional reference. This prototype changes presentation and interaction only.

## Preserve
- run/rest selection;
- date;
- distance and actual moving duration;
- optional ROF-J lifecycle entry;
- saved/recent course use and course-library navigation;
- steps and provenance;
- running format and RUN_WALK additional inputs;
- environment context;
- optional RPE;
- separate subjective/body-record screen;
- separate personal/shoes/insight screen;
- reflection / difference / next-check fields;
- memo;
- draft save;
- final save to Result.

## Mobile presentation
- Required run information stays visible.
- Optional groups use summary-first disclosure.
- Required completion is visible without scrolling to the bottom.
- Save remains available in a fixed bottom action bar once required data is complete.
- Recent courses use a horizontal strip rather than stacked full-width cards.
- Separate existing screens remain separate; they are not merged into the record form.
- Pinch zoom stays available; interactive controls suppress accidental double-tap zoom/selection locally.
- Scrolling must not accidentally activate horizontally scrollable course choices.

## PC
This version provides a basic wide layout only. Full PC review is deferred and must preserve the same functions.
